# エラーを直しながら進める例題

このディレクトリには、意図的にエラーを含めた Scala プログラム `fix.scala` と、それを段階的に直した `fix1.scala` 〜 `fix5.scala` があります。プログラムは 1 から 10 までの和を求めるもので、最後の `fix5.scala` が正しいプログラムです。

ここのファイルは sbt のビルド対象（`src`）の外に置いてあります。エラーを含むファイルが `src` にあると `sbt run` が動かなくなるためです。ここでは sbt を使わず、コマンドを直接実行します。

## 使い方

このディレクトリ（`fix`）で、次の 2 つのコマンドを使います。

```sh
scalac fix2.scala                                  # コンパイルする
scala run -cp . --main-class prg1.lx01.fix2.main   # 実行する
```

- `scalac` はコンパイルだけを行います。成功すると、ディレクトリ `prg1/` の下にクラスファイルができます。
  - クラスファイル（拡張子 `.class`）は、Scala のソースプログラムを JVM が実行できる形に変換した結果を入れたファイルです。Scala のプログラムは、ソースのままでは JVM で動かず、いったんクラスファイルに変換してから実行します。
- `scala run -cp . --main-class クラス名` は、コンパイル済みのクラスを実行します。`-cp .` は、クラスファイルを現在のディレクトリから探すという指定です。
- クラス名は、ファイルの 1 行目の `package` の宣言に `.main` をつけたものです。たとえば `fix3.scala` なら `prg1.lx01.fix3.main` です。

最初の 1 回は、コマンドが動き出すまで時間がかかることがあります。

## 各ファイルの内容と実行結果

| ファイル | 状態 | `scalac` の結果 | 実行結果 |
|---|---|---|---|
| `fix.scala` | `def aux(...) {` の書き方と、トップレベルの `println` | 構文エラーが 2 件 | （コンパイルできない） |
| `fix1.scala` | `println` を `def main` の中に移した | 構文エラーが 1 件 | （コンパイルできない） |
| `fix2.scala` | `aux` に `: Int =` を付けた | 成功 | 「メイン・クラス…を検出およびロードできませんでした」 |
| `fix3.scala` | `def main` に `@main` を付けた | 成功 | `1 + 2 + ... + 10 = 11` |
| `fix4.scala` | `simple(10, 1)` を `simple(1, 10)` にした | 成功 | `1 + 2 + ... + 10 = 56` |
| `fix5.scala` | `simple(1, 10)` を `simple(0, 10)` にした | 成功 | `1 + 2 + ... + 10 = 55` |

### fix.scala と fix1.scala：構文エラー

```
-- [E040] Syntax Error: fix1.scala:4:26
4 |  def aux(a: Int, i: Int) {
  |                          ^
  |                          '=' expected, but '{' found
```

関数の定義では、引数のリストのあとに `: 戻り値の型 =` を書きます。`{` の前に `=` がないというのがこのエラーの意味です。`fix.scala` には、これとは別に「トップレベルに実行文は書けない」というエラーもあります。実行文は `def main` の中に書きます。

### fix2.scala：コンパイルはできるのに実行できない

```
エラー: メイン・クラスprg1.lx01.fix2.mainを検出およびロードできませんでした
原因: java.lang.ClassNotFoundException: prg1.lx01.fix2.main
```

`def main` があっても、`@main` が付いていないと、プログラムの入口になるクラスが作られません。そのため、実行するクラスが見つからないというエラーになります。`fix3.scala` のように `@main` を付けると、このクラスが作られます。

### fix3.scala 以降：実行はできるが答えが違う

`fix3.scala` は 11、`fix4.scala` は 56 と表示し、どちらも正しい答え（55）ではありません。エラーメッセージは出ないので、プログラムを読んで原因を探します。

- `simple(a, n)` は、`a` に 1 から `n` までを足した値を返します。1 から 10 の和を求めるには、`a` に 0 を渡します。
- `simple(10, 1)` は `10 + 1 = 11` を、`simple(1, 10)` は `1 + (1 + ... + 10) = 56` を返します。

## 後片付け

実行すると、次のものが作られます。不要になったら削除してください。

```sh
rm -r prg1 .bsp .scala-build
```

## おまけ：java コマンドで実行する

`scalac` が作ったクラスファイルは、`java` コマンドでも実行できます。ただし Scala のライブラリ（jar ファイル）の場所も教える必要があります。次の例は `fix5.scala` の場合です。

```sh
scalac fix5.scala
java -cp ".:$(cs fetch --classpath org.scala-lang:scala3-library_3:3.9.0)" prg1.lx01.fix5.main
```

`cs fetch --classpath ...` は、Scala のライブラリの jar ファイルの場所を調べて表示するコマンドです。`-cp` の `.` は現在のディレクトリ（クラスファイルの置き場所）、`:` は区切りです。実行結果は `scala run` のときと同じ `1 + 2 + ... + 10 = 55` です。
